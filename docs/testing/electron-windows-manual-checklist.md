# DoTodo Windows 人工验收清单

自动化脚本 `npm run verify:win` 能证明代码逻辑、存储、IPC、交互和打包产物是好的。它**不能**证明这些东西：

- 透明无边框窗口在你的显卡和缩放比例下真的好看、真的能拖动；
- 托盘图标在通知区域里能看清、右键菜单能点；
- 全局快捷键没有被输入法或截图工具抢走；
- 多显示器和混合 DPI 下窗口不会被拉伸或跑到屏幕外；
- 跨日归档和损坏恢复在真实数据目录里按预期发生。

### 哪些已经自动化了（不用你重复验）

`npm run ui-check` 会在真实渲染进程里重放下面这些操作，并断言 DOM：

| 已自动覆盖 | 对应下面的编号 |
| --- | --- |
| 添加、勾选、双击编辑（Enter 提交 / Esc 取消） | 2.1–2.7 |
| `Space` / `F2` / `Delete` / `Alt+↓` 键盘操作 | 2.8–2.11、2.18 |
| **指针拖拽换位，以及拖出列表取消** | 2.16、2.17 |
| 删除后的撤销条、倒计时动画、撤销回原位 | 2.13、2.15 |
| 页面切换、历史行的只读性与延续按钮可见性 | 3.1–3.3、3.8、3.9 |
| **历史任务延续到今天，以及「终身只能延续一次」** | 3.4–3.7 |
| **跨日归档**（用「日期是昨天」的存档，不用改系统时间） | 4.2、4.3 |
| **系统日期回拨的保护** | 4.5 |
| **主文件损坏 → 保留证据 + 从备份恢复** | 9.7 |
| **两份都损坏 → 两份证据都保留 + 应用仍可用** | 9.8 |
| **警告里带具体恢复文件绝对路径** | 9.9 |
| **底色是中性灰（不是蓝色）、alpha 固定 0.88、三级文字在纯白壁纸上都达到 WCAG AA、正文不透明、标题栏可拖动** | 1.1、1.5、1.6、1.10 |
| 设置面板的每一项、**没有**透明度滑杆 | 1.10 |
| 界面上不该出现的四类噪音 | 1.11 |

「字看不清」这件事现在是**算出来的**，不用你判断：`visual-system.js` 会取每个文字元素的
计算样式，把它和面板的合成底色（分别压在纯白和纯黑壁纸上）算 WCAG 对比度，
低于 4.5:1 就失败。面板半透明意味着最坏情况是压在亮壁纸上，那正是这个问题最早暴露的场景。

改 `styles.css` 里的 `--ink` / `--ink-dim` / `--muted` 之前先跑一次，它会直接告诉你
新的数值够不够。

跑一遍就能看到结果，每个场景还会留一张截图：

```powershell
npm run ui-check
```

**逻辑正确性不用你负责了。** 下表里这些项仍然保留，但你现在要验的是**手感**——
动画顺不顺、点击跟不跟手、颜色在你显示器上到底好不好看。这些自动化永远看不到。

两个仍然只能人工做的跨日场景，原因写在下面：

- **4.4**（不关应用、改完系统日期再添加任务）：自动化注入不了"应用运行到一半时钟变了"这件事，
  只能真的去改系统时间。它走的是 `prepareCurrentDay` 那条路径。
- **4.6**（把日期调回正确值后警告消失）：需要真的改两次系统时间。

下面每一项都要亲手做一遍。每条都写了**怎么造出条件**和**应该看到什么**，做不到就是缺陷，记下来。

## 0. 准备

```powershell
cd F:\杂\转开发\DoTodo
npm install
npm start
```

数据目录（下面会反复用到）：

```text
%APPDATA%\dotodo\state.json
%APPDATA%\dotodo\state.backup.json
```

不确定时让应用自己报：

```powershell
npm run paths
```

> **装好之后注意**：安装版和 `npm start` 开发版共用同一个数据目录，也共用同一把单实例锁。
> 两个同时开着，后启动的那个会**静默退出**（退出码 0）。这不是崩溃——先关掉一个。

录屏或截图记录第 1、3、7 项的证据。

## 1. 窗口外观与交互

| # | 操作 | 期望 |
| --- | --- | --- |
| 1.1 | 观察主窗口 | **中性灰**半透明卡片（不是偏蓝的深色），圆角，1px 描边，无系统标题栏，四周有投影 |
| 1.2 | 鼠标按住标题栏空白处拖动 | 窗口跟随移动，松手后停住；不会选中文字 |
| 1.3 | 拖动窗口右下角 | 可以缩放，最小不小于大约 330×420 |
| 1.4 | 关闭再打开 | 窗口回到上次的位置和尺寸 |
| 1.5 | 把窗口拖到**亮色**壁纸或白色窗口前面 | **文字、勾选框、按钮依然清晰**；面板仍是灰的，不泛蓝 |
| 1.6 | 把窗口拖到**深色**壁纸前 | 面板边界仍看得出来（描边生效），不会和背景糊成一片 |
| 1.7 | 系统设置里切到浅色主题 | 界面保持深色玻璃，不出现白底黑字的错乱 |
| 1.8 | 系统开启「减弱动态效果」后重启应用 | 不再有入场动画和过渡 |
| 1.9 | 观察所有按钮 | 鼠标悬停有反馈；键盘 Tab 能走到每个按钮并有焦点圈 |
| 1.10 | 打开设置 | **没有**透明度滑杆；只有窗口层级、关闭到托盘、开机启动、数据、数据目录 |
| 1.11 | 通读整个界面找噪音 | **不该出现**：底部的 `Ctrl N` 快捷键提示、切换窗口层级时的说明弹窗、任务行上的「延续」角标、快捷键冲突警告。真错误（保存失败、数据损坏）仍然会出现，但只是一行细提示，**不遮挡标题** |

1.5 是最重要的一条。**背景透明度是固定的**（中性灰 88%），界面上不提供调节入口——
可读性不该是用户能调坏的设置项。如果文字在亮背景下发灰难认，说明背景 alpha 被改低了。

## 4. 跨日归档（用改系统时间造条件）

| # | 操作 | 期望 |
| --- | --- | --- |
| 4.1 | 记下今天的任务和完成状态 | — |
| 4.2 | 关闭应用，把系统日期改到明天，重新打开 | 昨天整天的清单出现在历史页，**未完成项不会被自动搬到今天** |
| 4.3 | 打开 `%APPDATA%\dotodo\state.json` | 昨天的日期记录里 `closedAt` 有值，今天是一个新的空 `activeDay` |
| 4.4 | 不关应用，只把系统日期改到明天，然后在窗口里添加一条任务 | 应用在真正干活前先归档：上一次的清单进了历史，新任务进新的一天 |

4.2 和 4.5 是两条独立的产品规则，都要单独验。

| # | 操作 | 期望 |

| 6.1 | 按 `Ctrl + Shift + Space` | 窗口显示/隐藏切换，应用不在前台也有效 |

6.3 不必真的装一个截图工具，也可以临时改 `src/electron/shell-controller.js` 里的 `GLOBAL_ACCELERATOR` 成一个已被占用的组合（比如 `CommandOrControl+C`）来验证降级路径，验完改回来。
这是一条**静默降级**：不是致命错误，就不该占用界面顶部的提示位。

## 9. 数据导入导出与恢复（**用假数据做，不要拿真清单试**）

先备份：

```powershell
Copy-Item "$env:APPDATA\dotodo\state.json" "$env:APPDATA\dotodo\state.json.manual-backup"
```

| # | 操作 | 期望 |
| --- | --- | --- |
| 9.1 | 设置里点「导出」，选一个路径 | 提示「已导出到：…」，文件里是格式化过的 JSON，结尾有换行 |
| 9.2 | 点「导入」，在对话框里点取消 | **什么都不发生**，没有错误提示，当前清单不变 |
| 9.3 | 导入一个随便写的文本文件 | 提示「导入文件不是有效的 JSON 状态。」；**当前清单完全不变** |
| 9.4 | 导入一个字段被改坏的 JSON | 提示状态无效；当前清单不变 |
| 9.5 | 导入刚才导出的文件 | 提示导入完成；导入前的那份状态自动变成了 `state.backup.json` |
| 9.6 | 点「打开数据目录」 | 资源管理器打开 `%APPDATA%\dotodo` |
| 9.7 | 关掉应用，把 `state.json` 内容改成 `{broken`，重新打开 | 弹出警告说明主文件损坏并已保留原文件；清单从备份恢复；目录里出现 `recovery-primary-*.json` |
| 9.8 | 同样把 `state.backup.json` 也改成坏内容，重新打开 | 警告说明两份都损坏、原文件已保留；应用**停止写入**，不再是"看着能用其实存不下去" |
| 9.9 | 观察启动警告文字 | 警告里带有**具体的恢复文件绝对路径**，不是只说"文件损坏了" |

9.7 的恢复文件必须真的存在，路径要能在资源管理器里直接打开。9.8 之后如果还能正常保存，说明"停止写入"这个保护没生效。

## 10. 失败与边界

| # | 操作 | 期望 |
| --- | --- | --- |
| 10.1 | 把 `%APPDATA%\dotodo` 目录设为只读，然后添加任务 | 出现「保存失败：…」和"数据暂时只保存在内存中"的提示；**刚添加的任务仍在界面上** |
| 10.2 | 恢复目录权限后继续操作 | 能正常保存，警告消失 |
| 10.3 | 任务很多（200+ 条）时滚动和勾选 | 不掉帧，滚动条可用，勾选后视口位置不跳 |
| 10.4 | 连续快速勾选/取消同一项 | 最终状态与最后点击一致，不会因为响应乱序而错乱 |
| 10.5 | 启动过程中立刻关闭窗口 | 不产生 `state.json.tmp.json` 残留，也不出现半截 JSON |
