# DoTodo 设计说明

这份文档只回答一件事：**当时为什么这么选，以及哪些选择后来被真实使用推翻了。**

产品怎么用写在 `README.md`，几个核心词的定义在 `CONTEXT.md`，
逐层讲解在 `docs/learning/electron/`。这里不重复它们。

## 产品与学习目标

一张常驻桌面的每日清单，一套源码同时供两种用途：自己日常使用，以及作为学习
Electron 的完整样例。这两个目标偶尔冲突——教学会想要更多层抽象，自用会想要更少代码。
冲突时**以自用为准**：代码保持可以直接读懂，课程去解释这份代码，而不是为课程改造它。

## 技术选择

| 选择 | 理由 |
| --- | --- |
| 原生 JavaScript，不用 React/Vue/TypeScript | 让 Electron 自己的边界清晰可见。加不加框架不会显著改变 Chromium 运行时和安装包体积，却会挡住进程模型这条主线 |
| 不用前端打包器 | 渲染进程直接加载 `index.html`，改完刷新即见；引入打包器会让"页面是从哪来的"变得难答 |
| CommonJS | 主进程、Preload、领域与存储保持同一种模块风格；渲染进程只通过 `window.dotodo` 使用能力 |
| `node --test` | 领域层是纯 JavaScript，不需要浏览器或 Electron 就能验证，测试在 1 秒内跑完 |
| `electron-builder` | Windows 出 NSIS 安装器，macOS 出 DMG/ZIP，同一个配置段 |

## 进程与模块边界

一句话版本：**主进程拥有权限，Preload 是唯一出口，渲染进程只画界面，领域层不知道
Electron 存在。** 详细职责见 `CONTEXT.md` 与第 3 课。

关键约束：界面永远是主进程确认过的快照的函数。屏幕上不存在第二份真相，
所以"界面显示了什么"和"磁盘上是什么"不会各自漂移。

## 界面上做过的几次修订

这几条都不是"美化"，是被真实使用推翻的：

### 背景透明度不再可调

最初有一个透明度滑杆，面板 alpha 由设置里的 `--surface-opacity` 控制。
问题是：面板半透明意味着最坏情况是压在**亮壁纸**上，alpha 越低文字对比度越差。
把可读性做成用户能调坏的设置项是设计错误。

现在 alpha 固定为 `0.88`（`--surface: rgba(28, 28, 30, 0.88)`），滑杆和设置项都已移除。
文字三级的取值不是"看着顺眼"定的，是按 WCAG AA 算出来的——`test/ui/visual-system.js`
会取每个文字元素的计算样式，把面板底色分别压在纯白与纯黑壁纸上算对比度，低于 4.5:1 就失败。
现在最差一档是 `--muted` 的 4.7:1。

### 调色板改成近单色

原先的深蓝黑 `#0c1424` 会吸收壁纸色相，看起来像"一个蓝色窗口"而不是玻璃。

现在只有黑、白、灰三种调，唯一保留的颜色是完成态的低饱和灰绿 `#8fbfa6`——
整块面板只有黑白会难以扫读，完成/未完成需要一点色彩区分。

### 外圈那层灰框是 CSS 画的，不是系统投影

用户报过一次"整个界面外圈有一层灰色阴影"，当时把窗口的 `hasShadow` 关掉了。
**改错了地方** —— 后来他说"还是有一层灰色背景框"。

真正的原因在 CSS 里：`.app-shell` 上有 `box-shadow: 0 24px 60px rgba(0, 0, 0, 0.46)`。
而窗口只比面板大 **6px**（`body` 的 padding）—— 60px 的模糊半径全被窗口边界裁掉，
剩下的那点正好全落在这 6px 里，于是看上去就是围着面板转了一圈灰框。

怎么定位的：把窗口留在屏幕上截一张，挪出屏幕外再截一张，两张做差分 ——
差出来的区域就是应用实际占的像素。结果一目了然：

| 探针 | 修复前 | 修复后 |
| --- | --- | --- |
| 窗口左边缘中点 | 比壁纸暗 46/255 | 0 |
| 窗口角落 | 暗 5~12 | 0 |
| 第 0 行改动的像素数 | 388（满宽矩形） | 145（圆角轮廓） |

**边缘中点暗 46、角落只暗 5，这是阴影梯度的签名。** `box-shadow` 已经删掉，
`test/ui/visual-system.js` 加了一条断言盯着外壳的计算样式里 `box-shadow` 必须是 `none`。

教训：投影这类"溢出内容之外"的效果，和**窗口比内容大多少**是一对耦合量。
只调其中一个，症状会以完全不同的样子出现。

### 窗口层级整套删掉了

曾经有「普通 / 置顶 / 桌面」三种窗口层级，标题栏有一个按钮、设置面板有一个分段控件、
托盘菜单还有一个勾选项。现在全没了，窗口固定为**不置顶 + 不进任务栏**。

删掉的理由不是"做不到"，而是**它是一个用户得先学会、才能做选择的概念**：三种层级之间的差别
要解释半天，而用户真正想要的只有一句话——一个常驻桌面的小部件。把这句话变成三个选项，
是让用户替产品做决定。

层级这个概念仍然是删掉的：用户不该先学三个选项才能做选择。留下来的是一句话——
**它就是一个桌面小组件**，而且现在真的挂进了桌面层（见下一节），不是"看起来像"。

`settings.windowMode` 作为历史字段留在 schema 里，老存档照常加载，界面和 IPC 都不再碰它。

### 桌面层：真的挂进桌面

窗口用原生 `SetParent` 挂进桌面，和桌面图标**同级**、画在图标之上。这件事 Electron
一个 API 都没暴露，只能自己调 user32（`src/electron/win32.js` 把 koffi 关在里面）。

**挂到谁。** 网上流传的做法是找**顶层**的 `WorkerW`，那套在这台机器（Windows 11）上
什么都找不到。这里的窗口树是：

```
Progman
  +- SHELLDLL_DefView -> SysListView32   图标层
  +- WorkerW                             壁纸层（Progman 的子窗口，不是顶层）
```

而壁纸层是**临时**的：实测一小时内它的句柄从 `0x90B12` 变成 `0x27C13BA`，又变成
`0x81264` —— 触发 Win+D、主题变化，Explorer 就会重建它。挂在它下面的窗口会跟着被销毁，
整个进程一起退出（这一条是真踩到的，不是推测）。挂到 `Progman`（全程稳定在 `0x1013A`）
才能活得和桌面一样久。

顺带一个反证：这台机器上的夸克桌面小组件**没有**走这条路，它的窗口是普通顶层窗口。
主流做法是"看起来贴桌面"。

**键盘。** 挂进去之后窗口的顶层祖先变成了 `Progman`，而键盘只发给"顶层窗口处于激活
状态"的那个窗口 —— 桌面永远不会被激活，所以点它的时候键盘是死的。修法是**点击时手动
补一次**：`SetForegroundWindow(Progman)` + `SetFocus(自己的窗口)`。桌面图标能收键盘
（在桌面上按方向键能选图标）走的就是同一条路。

这一步不能省，也不能少任何一半：`SetFocus` 在主进程线程里直接就能成功（窗口就是它建的），
**不需要 `AttachThreadInput`**；但必须先把桌面顶成前台，否则焦点设了也收不到键盘。

**降级。** 拿不到原生调用（不是 Windows、koffi 没装上、找不到 Progman、`SetParent` 被拒）
就安静地当普通窗口用，不报错、不弹窗。桌面层是加分项，不该让应用起不来。
挂载失败的原因会写进日志（`[DoTodo desktop] 没挂到桌面上：<原因>`）—— 否则这个功能
坏掉时是彻底静默的，只能靠"打字怎么没反应"去反推。

**测试入口下一律不挂。** 冒烟和交互场景会开出真窗口逐个断言，窗口一挂进桌面就脱离了
顶层窗口列表，`npm run ui-check` 那 296 条断言会全部扑空 —— 而且失败信息完全指不到
桌面层，只会看起来像"窗口根本没建出来"。`test/electron/main-wiring.test.js` 钉住了这条。

**这条的先例是背景透明度**：同样是"能做到但不该让用户选"。可读性不该是能被调坏的设置项。

### 快捷键冲突静默降级

全局快捷键被别的程序占用时（输入法、截图工具很常见），注册会失败。
原先会在界面上报警告，但用户无法处理这件事——托盘菜单里照样能显示窗口。

现在冲突只写进运行时状态，不占用界面的提示位。

### 去掉的三类噪音

- 托盘改设置后界面不同步的"延续"角标
- 底部 `Ctrl N` 快捷键提示（没人需要被告知这个）
- 快捷键冲突警告（理由同上）

## 验证是怎么分层的

每一层只证明一件事，别指望上一层覆盖下一层：

| 层 | 证明什么 | 命令 |
| --- | --- | --- |
| 单元 / 集成 | 领域规则、存储与恢复、IPC 校验、投影函数 | `npm test` |
| 静态约束 | 选择器对得上、渲染层不碰 Node、界面没混进不该有的元素、文档数字与脚本一致 | `npm test` |
| 冒烟 | 开发版里 Preload、IPC、DOM 真的连通 | `npm run smoke` |
| 交互场景 | 在真实渲染进程里点击、按键，断言 DOM 与磁盘结果 | `npm run ui-check` |
| 打包 | 产物体积分类、asar 内容、**打包版的壳层真的能启动** | `npm run verify:win` |
| 安装 / 卸载 | 装到临时目录、快捷方式与注册表、装好的副本能启动、卸载收干净、用户数据不被删 | `npm run verify:installer` |
| 人工 | 透明窗口在你的显卡与缩放下的观感、托盘、多显示器、干净机器上的覆盖升级 | 验收清单 |

两条经验写在这里，因为它们是踩出来的：

1. **"自动化通过" ≠ "可以发布"。** `verify:win` 全绿时它仍然会打印一句提醒去看人工清单。
2. **一个永远跳过的步骤等于没有验证。** 内存测量那一步原本会在"检测到已有实例"时跳过，
   而检测方式有缺陷，于是它长期在报"通过"却什么都没测。现在它用一次性数据目录启动，
   每次都真的执行。

## 打包上踩过的三个坑

### 原生依赖必须解包

`koffi` 带一个原生 `.node`。留在 `app.asar` 里它加载不了，而这里的降级又是"安静地当
普通窗口用"—— 开发时一切正常、装完之后功能没了，是最难查的一类问题。
`package.json` 的 `build.asarUnpack` 覆盖了 `node_modules/koffi/**`，
`test/electron/desktop-layer.test.js` 有一条守卫盯着这条规则。

注意 `verify:win` 那一步"打包版壳层启动"用的是 `--smoke-test`，而桌面层在测试入口下被
禁用 —— 也就是说**它证明不了打包版的桌面层能用**。这一条目前靠人工跑
`release/win-unpacked/DoTodo.exe` 验。

### Electron 42 起上游取消了 postinstall

`electron@41` 及以前的 `package.json` 有 `"postinstall": "node install.js"`，
`42/43/44` 没有。本项目锁的是 44.3.0，所以 `npm install electron` 会**成功退出但不下载二进制**，
二进制改成第一次用到时惰性拉取。

后果很具体：`node --test` 并行跑多个测试文件，其中几个会 `require('electron')`，
新克隆的仓库第一次 `npm test` 会有多个进程同时下载解压，撞出 `os error 183`。

修法是把它放回安装阶段：`tools/ensure-electron-binary.js` 挂在 `postinstall` 上，
二进制在就直接退出，缺了才调 electron 自己的 `install.js`。
**这种事不该让每个新克隆的人自己撞一次。**

### `Start-Process` 配合输出重定向时拿不到 ExitCode

实测：`HasExited` 为真、`ExitCode` 为空。任何"拿退出码判断成败"的断言都会变成
**什么都没检查却显示成功**。

因此验证脚本里所有关于打包版和安装器的断言都落在 stdout 的标记上
（`DOTODO_SMOKE_READY`、`DOTODO_SHELL_BOOT`），并且有一条守卫禁止在拿不到的地方使用 `ExitCode`。

## 明确不做

- 不引入 React、Vue、TypeScript、Redux、数据库或前端打包器；
- 不做账号、云同步、提醒、标签、优先级、项目、未来日程；
- 不在 Windows 上声称已完成 macOS 运行验收；
- 不为缩小数字删掉 Electron 运行必需的 Chromium / Node 文件。

## 仍然没有验证的事

诚实列在这里，不要从"测试全绿"推断它们没问题：

- **macOS 从未构建过。** 代码路径写了、配置写了，但这台机器上无法验证。必须在 macOS 上做。
- **干净机器上的覆盖升级、UAC 行为、杀毒软件误报**没有验过。开发机上残留的注册表和缓存
  会把问题盖住。`verify:installer` 只证明安装包的**结构**是对的。
- **人工验收尚未完成。** 透明窗口在你的显卡与缩放下的实际观感、托盘图标的清晰度、
  多显示器与混合 DPI，这些自动化看不到。
- **Explorer 重启会杀掉挂进桌面的窗口，而重建还没做。** 窗口是 `Progman` 的子窗口，
  `Progman` 一没它就跟着没，应用也会退出。日常使用里 Explorer 崩溃不常见，但这条路径
  目前是**没处理**的，不是"处理好了没测"。
- **桌面层没有做过网格对齐和多显示器验证。** 现在只是挂在桌面上，位置和尺寸还是普通
  窗口那一套；"占 2/4/6 个图标格"、DPI 变化、副屏都还没碰。
- **macOS 上不会挂载。** 那里没有 `Progman` 这类桌面宿主，代码会走降级分支变成普通窗口。
  这不是"未验证"，是设计如此。
