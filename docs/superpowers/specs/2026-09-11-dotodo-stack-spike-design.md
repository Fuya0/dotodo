# DoTodo Windows 技术栈验证设计


## 目的

用相同的最小桌面窗口行为为 DoTodo 选择技术栈，而不是凭框架宣传或示例体积做决定。验证产物只用于测量，验证代码不进入正式产品。

## 已确认的产品方向

- 本期只交付 Windows 10 22H2 与 Windows 11。
- DoTodo 是每日独立清单，不是项目管理或日历应用。
- 新任务只属于 Today；跨过本地午夜后，昨日清单成为只读 Day record。
- 历史任务不自动回到 Today。用户可通过 Continuation 在 Today 创建关联的新任务。
- 窗口提供普通、置顶、桌面三种层级；桌面模式使用公开的窗口 Z-order 能力，不绑定 Explorer 私有窗口。
- 关闭默认隐藏到托盘；托盘或全局快捷键可召回。
- 数据完全保存在本机，可导入/导出 JSON。
- 首版不打包、不上传 GitHub，待用户验收开发版后再处理发布。

## 候选路线

### WPF spike

- C# + XAML，目标为 .NET Framework 4.8。
- 使用 WPF `Window` 验证无边框、整窗透明度、Topmost 和位置记忆。
- 使用 `System.Windows.Forms.NotifyIcon` 验证托盘驻留。
- 使用 Win32 `SetWindowPos` 验证桌面层级。
- 优点：Windows 概念直接、系统集成成熟、目标机通常已有 .NET Framework 4.8。
- 风险：未来 macOS UI 基本需要重写；旧框架不代表现代跨平台方向。

### Tauri spike

- 原生 HTML/CSS/JavaScript + Rust + Tauri 2。
- 使用 Windows WebView2 渲染 UI；Rust 负责窗口、托盘和 Win32 扩展。
- 优点：复用现有 Web UI 思维，安装包通常显著小于 Electron，并保留 macOS 路线。
- 风险：需要 Rust/MSVC 工具链；业务层与平台层之间存在命令接口；WebView2 是系统依赖。

## 公平比较原则

两个 spike 都只显示标题、三条静态任务和一个层级状态，不接入正式数据模型。均构建 Windows x64 Release，记录：

1. 可分发文件大小；
2. 解压或安装后文件大小；
3. 冷启动到窗口可交互的主观与日志耗时；
4. 空闲 10 秒后的进程工作集；
5. 实现透明度、置顶、托盘、桌面层级所需的平台代码复杂度；
6. Windows 10/11 运行时依赖；
7. 未来 macOS 可复用范围。

体积比较必须注明是否依赖系统已有运行时。框架依赖版不能与完全自包含版混为同一口径。

## 决策规则

- 若 Tauri 安装/分发体积小于 30 MB、空闲内存小于 100 MB，且窗口行为无明显缺陷，选择 Tauri；它同时满足轻量和未来 macOS 路线。
- 若 Tauri 的透明窗口、桌面层级或 WebView2 行为存在阻断问题，而 WPF 可稳定完成，则选择 WPF。
- Electron 原型仅作为视觉参考，不进入正式实现。

## 学习交付

验证报告解释每个技术栈从源码到可执行文件的构建链。正式开发按以下循环记录：概念说明、设计选择、测试先行、最小实现、运行观察、练习题与复盘。

## 验收

- 两个 spike 均能构建或明确记录无法构建的具体环境阻断。
- 至少一个 spike 验证透明度、置顶、托盘和普通窗口行为。
- 生成可复现命令、体积数据和技术选择结论。
- spike 目录可整体删除，不被正式产品引用。
